# 实验性 MLX 流式识别

目前已经接通真正的增量音频推理和录音页面：每 160 ms 音频只编码一次，跨块保留卷积状态、Conformer 注意力缓存、GPT-2 KV cache 和位置计数。**这是可测试的实验实现，识别效果尚未对齐豆包原版，存在明显漏字和错字。** 非流式入口继续保留为默认模式。

## 启动

在仓库根目录，按主 README 安装 Python 依赖、从本机提取并完整导出模型后执行：

```sh
independent/.venv/bin/python independent/web_server.py \
  --model independent/exported-model --streaming --port 8766
```

打开 http://localhost:8766，使用支持麦克风和 16 kHz AudioContext 的 Chrome / Safari，点击“开始录音”，授权本机麦克风。录音过程中会更新文字，点击停止后冲刷句尾。页面显示首字时间、最近请求耗时、推理累计时间及收尾时间。17 秒自动停止，后端最多接收 18 秒。

需要完整导出中的 `stream_encoder`、`stream_decoder`、`stream_embedding`、`stream_position` 四个 safetensors，以及对应图、词表和 CMVN。旧的 `--scope nonstream` 三组件目录不能运行流式；可用 `export.py --output independent/exported-model-full` 导出到新目录，再指定该目录。导出器拒绝覆盖已有目录。

独立部署目录中同样可运行 `.venv/bin/python independent/web_server.py --streaming`。`package.py` 已包含这些运行文件；此前生成的部署文件夹/压缩包需重新生成才能包含本次新增代码。运行只读 safetensors 目录，不需要 FLUTE、豆包安装或私有推理库。未在第二台实体 Mac 上测试。

## 实现依据与边界

- 本地模型配置实际指定 `feat_win_size=16`、`encoder_input_T=16`、`audio_chunk_size=1`、`finish_pad_wav_ms=960`。每 16 个 10 ms 特征帧经两层卷积变成 4 帧，经 24 层 Conformer 和四帧拼接变成一个 1024 维音频向量。
- 流式解码器是 12 层 GPT-2 风格网络，16 个注意力头、学习式位置嵌入、GELU。这里没有调用非流式 Qwen3 风格解码器，也没有反复重跑此前整段音频来模拟实时输出。
- INT4 权重独立解包；当前用浮点矩阵运算和 INT8 激活舍入/裁剪模拟量化路径。音频向量与文本 token 交替进入解码器；控制 token 也写入缓存，随后等待下一块音频。它仍不是原版整数算子的逐 bit 对齐实现。
- 浏览器每 2048 个采样（128 ms）发送单声道 PCM16，服务端保留不足一个特征块的尾部。改为 997 个采样的传输分包，测试句在所有编码步上的文字完全一致。
- 推理模型常驻单一子进程。HTTP 只监听 127.0.0.1，检查 Host、Origin、随机会话 ID 和分包序号；并发录音会被拒绝。推理子进程使用 `offline.sb` 禁网，并禁止读取豆包安装/用户数据目录及已知私有运行库路径。录音只保留在内存中。
- 未实现 VAD 自动结束、长音频切段、上下文采集、ITN 数字格式化、非流式句尾纠错或完整控制 token 协议的逐层验证。停止后补的 960 ms 是计算用静音，不是强制等待 960 ms 墙钟时间。

## 2026-11-15 实测

Apple M4 Pro，macOS 26.2，Python 3.13，MLX 0.32.4。使用**页面相同 HTTP 接口和沙盒工作进程**，按真实音频速度分块回放两段合成语音和两秒静音。模型启动加载不计入首字时间。不是人工实录、标准准确率测试或原版数值一致性验证。

| 样本 | 音频长度 | 首字墙钟时间 | 每块计算中位数 | 每块最大计算 | 停止后收尾 | RTF |
|---|---:|---:|---:|---:|---:|---:|
| 开会/材料 | 5.916 s | 0.608 s | 108.8 ms | 191.6 ms | 0.438 s | 0.784 |
| 雨伞/图书馆 | 6.099 s | 1.245 s | 94.3 ms | 207.5 ms | 0.341 s | 0.716 |
| 静音 | 2.000 s | 无文字 | 92.9 ms | 154.0 ms | 0.486 s | 0.880 |

RTF = 累计模型处理时间（含句尾补静音）/ 原始音频时长。整体处理速度快于音频到达速度，但单块峰值可能超过 160 ms；不保证每台 Mac 都能实时。首字从回放开始计时，包含音频本身的前导静音、分包与计算，不能解读为相对于每个说话字的固定延迟。

实际结果原样记录：

| 参考内容 | 流式输出 |
|---|---|
| 你好，今天下午三点开会，请帮我准备十五份会议材料。 | 你好，今天下午三点开会，请帮我准备十五会议材 |
| 明天早上八点半，请提醒我带上雨伞，坐地铁去图书馆。 | 明天早上提醒我，带上雨伞做地铁书屋馆 |
| 两秒静音 | 空文本 |

因此本次只确认：增量计算、实时接口、缓存连续性和测试机上的处理速度已跑通；**准确率仍不达标，不能宣称与原版效果一致或完整复现完成**。浏览器页面已检查；内置浏览器的麦克风请求未完成，真人麦克风录音质量尚待实际测试。
